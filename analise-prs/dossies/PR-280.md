## Conteúdo do Fix

A PR corrige 3 bugs no script `gen-migration-probes` (script de auditoria de schema do banco):

### 1. DROP Reconciliation

**Problema:** objetos que eram `DROP`ados em uma migration não eram reconhecidos corretamente na fase de reconciliação do probe. O comparador de estado esperado vs. estado atual ignorava objetos removidos, causando falso negativo (probe dizia "ok" quando a migration tinha removido uma tabela/coluna que o probe esperava existir).

**Fix:** reconciliação agora considera objetos com `DROP` como intencionalmente ausentes e não os inclui no conjunto de "esperados".

---

### 2. `schemaname` Ausente

**Problema:** queries de probe sem qualificação de schema falhavam silenciosamente quando executadas em schemas diferentes de `public`. A query usava o nome da tabela sem prefixo de schema, e o `search_path` do Supabase pode não incluir o schema correto.

**Fix:** todas as queries de probe agora incluem `schemaname` explícito (qualificação completa `schema.tabela`), garantindo funcionamento em qualquer schema do banco.

---

### 3. `policy cmd` Incorreto

**Problema:** o valor de `cmd` (comando de política) retornado pelos probes de RLS estava incorreto. A query usava a coluna errada ou mapeamento errado do enum do Postgres para os valores de comando (`SELECT`, `INSERT`, `UPDATE`, `DELETE`, `ALL`).

**Fix:** mapeamento corrigido para usar `pg_policies.cmd` com o valor correto, garantindo que probes de RLS identifiquem corretamente o tipo de comando de cada política.
